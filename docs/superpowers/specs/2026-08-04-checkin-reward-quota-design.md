# 签到奖励与配额变化设计

## 目标

持久化 WorkBuddy/Qoder 签到返回的奖励积分，展示签到前后配额变化，并按配额包显示各自到期时间，避免“已签到但积分未变化”无法区分。

## 范围

- checkin_attempts 保存 reward_credits、签到前后配额快照及可比较的余额差值。
- 签到执行成功或已确认当天签到后，立即触发对应账号的配额采集。
- Qoder 与 WorkBuddy 的配额包保留 expires_at；缺失或不可解析时不虚构时间。
- 管理接口返回脱敏的奖励、配额前后值、差值和到期时间。
- 签到中心与账号详情的签到历史显示奖励积分、变化结果和配额包到期时间。

## 数据流

1. 签到执行器在调用上游前读取该账号最近可用配额快照作为 quota_before。
2. 上游返回 CLAIMED 或 ALREADY_CHECKED_IN 后，立即调用对应的配额客户端。
3. 将采集结果规范化为配额包列表（名称、remaining、total、unit、expires_at），计算每个包及总 remaining 的差值。
4. 事务内写入签到尝试及 daily state；采集失败不覆盖签到结果，差值保持未知。
5. API 只返回结构化、脱敏字段；前端按配额包紧凑展示。

## 状态判定

- CLAIMED 且签到后总余额增加：刚刚领取成功。
- CLAIMED 但余额未增加或刷新结果不可用：已领取，余额未变化 或 已领取，余额待刷新。
- ALREADY_CHECKED_IN：今日已签到，不再重复 claim；若有 reward_credits 仅展示上游报告的奖励额度，不宣称本次新增。
- 未提供奖励字段时显示 未返回奖励，不显示 0。

## 到期时间

Qoder 的用户配额、附加配额分别显示各自 expires_at。WorkBuddy 只在上游返回有效到期字段时显示；没有字段显示 未提供到期时间。时间统一转换为北京时间展示，原始 ISO/毫秒时间仅在服务端规范化，不写入敏感日志。

## 兼容与迁移

新增 SQLite 列使用幂等迁移；历史行字段为空时前端显示未知，不回填虚假奖励。旧版本读取接口继续可用。

- SQLite 迁移与回滚事务测试。
- 管理接口和 Vue 签到历史结构化展示测试。
