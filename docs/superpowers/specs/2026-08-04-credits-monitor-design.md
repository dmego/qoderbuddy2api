# 积分监控页面设计

## 目标

在账号池下提供一个独立的积分监控页面，汇总显示当前积分、积分变化趋势和按时间筛选的账号快照，并提供自动刷新与立即刷新指标操作。

## 范围

- 复用现有 `/metrics/accounts`、`/metrics/accounts/{provider}/{account_id}`、`/history/points` 和 `/metrics/refresh` 接口。
- 前端按账号并发读取积分历史，在浏览器内按时间窗口过滤、汇总和绘图。
- 新增导航路由 `/credits`，不改变后端 schema、采集器或凭据边界。
- 自动刷新仅刷新页面查询；立即刷新指标触发现有异步采集操作并轮询结果。

## 页面结构

1. 顶部摘要：当前积分总量、可用账号数、最近采集时间、窗口内变化。
2. 筛选栏：服务商、账号、时间窗口快捷项和自定义起止时间。
3. 趋势图：全部账号汇总或选中账号的积分平滑曲线，使用现有 ECharts 封装并支持悬浮查看数据。
4. 账号积分表：当前积分、单位、变化量、采集时间和状态。
5. 操作反馈：自动刷新间隔开关、立即刷新指标、错误与部分数据不可用提示。

## 数据与错误处理

- 只有有效的积分或配额剩余值才进入摘要、曲线和表格；未知、过期或接口失败不转成 0。
- 单个账号历史失败不会阻塞其他账号；页面展示部分数据不可用提示。
- 自动刷新可选关闭、30 秒、1 分钟、5 分钟，默认关闭，避免后台额外请求。
- 时间筛选以浏览器本地时间输入转换为 ISO 字符串比较。

## 验收

- 导航可进入页面，页面能读取当前账号积分并按时间绘制曲线。
- 筛选改变后摘要、图表和表格同步变化。
- 自动刷新和立即刷新指标有可见状态反馈。
- `npm run typecheck`、`npm run lint`、`npm run build` 通过，`git diff --check` 无错误。
